# P9 实机核实条件与实现边界

本轮仅使用锁定源码和本地缓存，执行注入 libusb / Linux syscall 的离线测试。
没有连接 C3XL、枚举真实 Panda、发送真实 CAN，亦未修改系统、切槽、重置或刷写。
真实配置见 `profiles/unbound.json`：两个槽位和角色均未绑定，权限均为 false。
该文件是审阅模板，不是可直接启动设备的配置；P9 没有新增生产启动器或 JSON 加载入口。

## 已实现的边界

- USB：显式许可后才可原生枚举。正常固件候选必须构成完整、有限库存；额外、重复、
  不可打开的候选都拒绝。UID、板型、ABI、128 字节应用签名精确读回；只有显式识别
  的 F4 候选签名才请求能力扩展。发现不 claim，不发控制 OUT，也不重置或改配置。
- 激活继续使用原句柄，要求本次 lease 的 alt0 证据并再读身份，防止串号相同的替板。
  USB 底层有单独受限 noOutput 控制写/CAN TX 开关；P9 绑定桥不授予这些开关，且
  最终 handoff 再次禁止所有 OUT 与具有副作用的 vendor IN。不能绕另一块板发送。
- SPI：只能打开明确指定且有外部关联证据的字符设备，核对 major/minor 和已有配置。
  发探测帧前要求 mode 0、8 bit、明确频率且不超过锁定实现的 50 MHz 上限；该上限
  **不是任意频率均已实机兼容**的证明。不会设置 SPI 配置、GPIO 或 reset。
  SPI 的“只读”指固件请求语义，获取身份仍主动发送 SPI 帧，并非被动监听。
- 每个 SPI 协议事务持有 advisory flock；未知消耗、短传输、超时、时钟回退、解锁失败
  和取消均封锁相应会话。保留同一个 fd，不自动重开或重放不确定操作。
- typed profile 校验要求完整两板、固定槽位、精确原始身份、明确外设角色与外部证据
  校验回调。板型、UID、外观、描述符和原始签名都不单独证明精确 MCU 或启动信任。
  无外部校验器、证据缺失或任意字段不符，输出 UNBOUND；不会自动猜测绑定。
- 原生候选为 `NATIVE_READ_ONLY_BOUND`，与旧 `SYNTHETIC_BOUND` 测试 profile 分开。
  结构匹配不授予设备访问、控制或部署权限。回调必须核验原始证据内容及板卡关联，
  不能把 JSON 中的哈希/true 字段当作证明；本阶段没有真实证据校验实现。
- 保留 lease 一次移交现有 runtime owner，继承双板 epoch/过期/整组退休规则。
  不自动续写探测时间；过期需重新完整探测。只读桥拒绝运行初始化所需控制 OUT，
  因此运行健康/安全屏障不能据此通过，车辆控制及重新接合权限继续关闭。

## 后续必须实机核实

| 优先级 | 条件 | 验收要求与当前缺口 |
|---|---|---|
| 1 | 每块板的真实身份与 firmware | 精确 MCU 型号、板卡/线路版本、UID/串号关联、实际固件版本、完整应用签名与 ABI 证据一致；不能由 DOS/F4 字样推定 STM32F413。当前未知，保留 UNBOUND。无需厂家照片也可先收集经授权的软件证据，但其无法证明的物理项继续待定。 |
| 1 | 完整拓扑、端口及独占条件 | 明确本地板/外置 Panda 各自供电、USB 端口或 SPI 节点，排除额外候选和自动重置/刷写服务。先记录现有服务及恢复条件，另行确定允许的台架操作。 |
| 1 | USB 当前接口状态 | 核实同一 lease 的实际 active alt0、claim 权限、内核驱动占用及串号稳定性。锁定固件不支持 GET_INTERFACE；“描述符中存在 alt0”不等于它已激活，禁止用 SET_INTERFACE/reset 猜测修复。 |
| 1 | SPI 节点、配置与线协议 | 精确 path ↔ 板卡映射、字符设备号、mode/bits/speed 与证据一致；确认独占与其他进程是否遵守 flock。非零 wire request-ID 并不能证明跨进程/断电的新鲜性，需设计并验证持久或设备协商策略，避免 MCU 最近请求缓存复用。 |
| 1 | 恢复链 | 独立确认可用备份、槽位/引导状态、进入恢复与回退的方法及信任链；本阶段未进入恢复、切槽或刷写。可恢复性不足继续阻断部署。 |
| 2 | I/O 时序、取消与故障 | 真实 Linux USB enumerate/open/claim、SPI 同步 ioctl 不能被当前代码强制抢占。O_NONBLOCK 也不是硬超时证明。离线只验证调用前后预算和错误封锁；需目标板测量最坏延迟、拔板/断电、取消、重连及双板隔离。 |
| 2 | 生命周期与运行许可 | 在另行授权台架范围内核实只读探测的最坏耗时是否满足现有 10 ms freshness 窗口；设计持续发现/探测和运行受限写许可，完整健康、安全及 heartbeat 屏障通过前禁止运行接合。当前无生产启动入口。 |
| 2 | 外设与总线路由 | 验证两板 CAN 总线、harness/点火、风扇/供电、诊断及不支持的外设角色；先采集后匹配，不能靠枚举顺序分配。F4 候选不声明 CAN FD、SPI 或 IR。 |
| 3 | 其余整车门槛 | 目标 MCU 最坏栈/中断占用、驾驶员监控硬件方案与告警、宋 PLUS 实车信号验证、控制器与专用 safety、封闭场地验证仍是独立工作。C3XL 无驾驶员相机这一产品事实不构成关闭监控的理由。 |

单 H7/SPI 与 USB/SPI 混合的模拟通过仅证明源码接口和拒绝路径；不证明用户板卡
就是相同 MCU，也不证明接线、运行频率、恢复或整车安全。默认原 SPI 路径保留；
实际 pandad 在隔离 Linux 环境仅执行原有 offline 入口，活动设备参数仍被拒绝。
