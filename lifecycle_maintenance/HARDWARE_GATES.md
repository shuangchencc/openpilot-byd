# P10 后必须实机核实的条件

本轮可以在必要时连接 C3XL；离线测试不能证明以下条件。用户现有 C3XL
产品配置不带驾驶员相机/SIM 功能，驾驶员监控缺失仍是实际运行前必须解决的
条件。外观相似、静态 JSON、哈希和离线 PASS 都不能替代物理证据。

| 优先级 | 下一步 | 验收标准与边界 |
| --- | --- | --- |
| 1 | 单独供电下被动核实系统与恢复链 | 只读核实系统/内核、分区/槽、备份完整性、可用恢复工具和板卡供电路径；证据绑定明确设备与采集时间。仍不切槽、刷写、复位或试跑恢复。 |
| 2 | USB/SPI 身份与独占权 | 核实两块板实际 MCU/板型、UID/serial、firmware signature、协议与 F4 capability；固定槽位/角色与物理线束对应。USB active interface/alt0、内核驱动占用，SPI char node/rdev/mode/bits/speed必须对应证据。没有外置板时整组不可用。 |
| 3 | SPI 固件语义与全部访问者 | 确认实际固件使用已锁定 one-entry ID/CRC cache、4096字节CS/DMA边界与 UID 请求语义；枚举所有服务/进程/别名节点，证明所有 master 都遵守同一节点 flock。现有旧 SPI 客户端不自动满足该条件。若需停止服务或新增主动探测，另列明确操作范围。 |
| 4 | 台架故障、内核期限和资源 | 经明确台架方案验证枚举/claim/open/ioctl、掉板、半读、迟到、取消、重复断连、进程退出/崩溃、重新接入；测 worst-case时延、内存/线程/栈、锁持有、退出响应、供电异常。卡住时必须整组撤销且不新增lane。不能仅用平均值或事后timeout检查证明硬期限。 |
| 5 | 无输出 runtime 与恢复演练 | 在核实恢复前不安装候选。以后验证逐板health/safety/heartbeat、退出规则、外围角色、完整组条件、跨epoch无旧消息、拒绝后不得绕板发送；先保持 noOutput。执行器只读代理不授予safety配置/heartbeat写权限，真正生产verifier与启动器仍待实机阶段实现。 |
| 6 | 完整 openpilot 与车型验收 | 解决驾驶员监控和声音告警；验证相机、标定、时间同步、热/电/算力资源；宋 PLUS真实信号和控制器、独立Panda safety、线束总线映射分别验收。封闭场地分级验证后再考虑道路使用。 |

任何真实绑定必须验证证据内容与两板身份、精确固件/协议、角色、维护链、当前
process epoch 和 discovery revision 一致。SPI gate 每次读取当前保留 backend
的 live proof；不能复用 handoff 前的审批结果。当前发布物不带真实证据 verifier，
默认启动直接拒绝，不提供环境变量/普通 serial/旧 SPI fallback 的绕过入口。

只读原生访问也需要先证明所使用 control-IN 确实无副作用；未知厂商固件不能
直接套用官方请求。必要的设备测试不能使用会自动 reset/flash 的 Panda 构造器
或旧启动脚本。照片/厂家资料缺失时允许继续离线开发，但保留身份未知状态。
