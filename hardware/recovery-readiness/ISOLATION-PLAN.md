## 按步骤推进与验收

| 顺序 | 具体工作与验收 | 当前状态 |
| --- | --- | --- |
| I0 只读基线 | 锁定来源、当前 slot/root、设备映射、句柄持有者及祖先、启动文件摘要、容量；每项记录时间与权限缺口 | 已取得本轮样本；不构成排他访问证明 |
| I1 返回方案 | 核对实际加载的 comma.service 与 drop-ins、ExecStart/ExecStop/KillMode/Restart/触发源；审查当前 comma.sh、动态脚本及 wrapper 的相关分支；保存本次操作所需配置/软件子集 | 部分完成；停止/重新启动副作用仍有未知 |
| I2 服务隔离 | 后续明确允许时，以已核实 unit 为操作对象；先记录原 active/substate、job、cgroup 与启动来源，再执行一次约定的停止动作；核对 unit 已停止、无待执行启动任务、相关 cgroup/进程/句柄均退出 | 本轮禁止执行；不以 kill 两个叶子进程代替监督隔离 |
| I3 排他访问 | 排除监督者重拉起、其他进程/设备别名/master；完整可见性扫描不得有未知缺口；观察期至少覆盖已确认的重启/重探测周期，随后由同一测试会话持有所有权并持续监测 | 未完成；无 flock 记录或多次空扫描不能单独通过 |
| I4 单板身份 | 明确物理供电、节点↔板关联与无车辆连接；采用独立、已审查、无构造器副作用的工具；同会话取板型、UID关联、版本、完整 app 签名、协议证据 | 未执行；不直接启动 P10 生产入口 |
| I5 双板身份与角色 | 每板独立验收后形成完整库存；排除 USB/SPI 指向同一实体；外置板端口/供电明确后另行接入；固定槽位、角色、拓扑证据一致 | 未完成；不能把一个 USB 候选加一个 SPI 节点计作两板 |
| I6 退出/交接 | 关闭诊断会话、释放其句柄并验证无残留；按照已审查的返回方案恢复约定状态，再复核原系统和通信；身份合格后才审阅绑定候选 | 未执行；不会自动 restart/reset/flash 作为清理 |

I1 不要求先做破坏性的全机恢复演练。它要求与本次隔离影响相称的恢复材料和可信返回方法；
应用退出、主机启动恢复、MCU bootstub 恢复必须分开。主机只读材料采集可与 I1 并行，
不因 I3/I4 未完成而暂停无关的备份准备。

I2 的具体命令在核实加载态及停止脚本后才能冻结；目前给出确定的 unit、检查对象、前后状态
和失败分支，不编造一条可直接运行的 stop/start 脚本。第一次隔离应由人在场监督，SSH连接独立于
目标 unit；超时预算根据实际 ExecStop/KillMode 定义，不能把磁盘 TimeoutStopSec=1 当作硬期限。
超时或残留时保留只读证据并停止主动板卡访问，不追加 kill/reset 来制造“成功”。

I3 需要补足权限可见性及非进程 master 证据。是否需较高权限的**只读检查**要具体说明范围；
当前入口未提权。进程观察与未来同会话所有权互补，单次扫描不能消除 scan→open 的竞争窗口。
旧 SPI 客户端使用逐事务 advisory flock；它不能证明其他进程遵守锁，也不能替代 P10 会话期所有权。

## 身份查询必须先解决的协议差异

下表是与现机选定磁盘 API 摘要一致的**本地源代码行为**，不是实际 MCU 回答，也不是已批准发送清单。
API SHA256 为 `1f99943744e7b286f0e7fcc46ca9f24669676a168548269f12084d3fc38450bf`。
它不能证明板上固件实现了这些请求或该请求没有其他副作用。

| 目的 | 磁盘 API 使用的 vendor IN 请求 | 后续约束 |
| --- | --- | --- |
| 板型 | 0xc1，wValue/wIndex=0，请求上限 64B | 解析已审查的具体响应形状，不能由 DOS 枚举推定精确 MCU |
| UID 关联 | 0xc3，0/0，12B | 原始身份留在私有证据，公开摘要脱敏；不能把UID当信任证明 |
| 版本 | 0xd6，0/0，上限 64B | 有界解析；字符串不是完整固件证明 |
| app 签名 | 0xd3 与 0xd4，各 0/0、64B | 两段完整128B，绑定同一会话和实体；与已知产物比对 |
| packet versions | 0xdd，0/0，3B | 现有 P10 要求8B ABI；不可把3B响应补零、截断适配或直接判兼容 |

未来只允许经固件语义审查的请求；不要把所有 vendor IN 都视为无副作用。
不调用 Panda 构造器，不运行现机 wrapper，不自动 recover/flash/reset，不读 provisioning secret。
0xd0 的设备配置/secret 请求不在本计划身份采集目标中；不发 heartbeat、安全模式、清队列或其他 OUT。

USB 打开/claim 与现有接口状态、内核驱动占用的判断另行安排；不自动 detach、SET_INTERFACE、reset。
SPI 获取身份需主动发送帧，不能称为被动监听；须先核实实际 mode/bits/speed、关联和独占，且解决
旧协议与 P10 请求 ID/新鲜性策略的对应关系。未知请求状态不能重试或绕到另一板发送。

不要求照片或厂家资料。能用软件证据确认的先做；精确 MCU/线路版本、bootstub、OTP、物理恢复口等
无法据此证明的项目继续标为未知，不能用外观、描述符或历史版本推断。

## 中止与返回分支

- 基线、来源或拓扑变化：退出本次检查，重新采样关联；保持 UNBOUND。
- 停止动作/监督逻辑无法解释、持有者残留或重新出现：不进入 I/O；不自动升级为 kill/reset。
- UID/签名/ABI/长度不符、读取超时或未知消耗：封锁本次会话，不自动重开、重放或绕板请求。
- 退出时只释放由诊断创建的资源。原服务启动会触发未经审查路径时，不把自动启动作为 finally 清理。
  具体执行前必须明确“返回已审查原栈”或“保持受控停机等待处理”的可接受分支；目前尚未具备。
- 供电/车端连接状态改变、失去在场监督或预定退出路径：结束试验，不执行写盘/刷固件补救。

身份和独占通过以后仍只是下一阶段入口。实际 health/safety/heartbeat、消息有效性、故障/时序、
无输出观察、双板路由、驾驶员监控与宋 PLUS 实车信号验证均保留各自验收；没有任何自动解锁生产行为。
