## 固定读取边界与保存方式

读取前核对 LUN 容量、4096B 扇区、分区号/名字/起止 LBA、分区节点的设备类型和 rdev，以及当前
GPT 内容和挂载/slot 关系。分区节点读取范围严格为 `[0, expected_bytes)`，不跟随任意路径或
未知设备类型；发现映射漂移、长度不符或权限不足，失败该对象，不改权限或改用未经审查的接口。

GPT 读取先核对 header 自身签名、形状、CRC、主备位置和 usable 范围：`first_usable >= 6`，
`last_usable <= total_sectors - 6`，两份 entries 都必须落入对应固定元数据窗口。再读取这些小
窗口。sde 已知备用 header 的 entries CRC 错误应原样保存并明确标记；采集不得顺手修复 CRC、
属性、类型 GUID 或槽状态。原始 GUID 仅留在私有材料中。

使用现有主机备份父目录 `/Users/shuang/Code/openpilot/migration-audit/` 下的新 capture-set 目录，
不覆盖旧备份；新目录 0700，原始归档及私有回执 0600。目录不能位于工程跟踪范围或共享发布位置。
开始前至少确认 30GiB 可用空间，运行时保留至少 4GiB 余量；以实测容量为准，不复用前轮瞬时值。
如果接收器采用压缩，仍按未压缩最坏容量预算，不能假定零页压缩比。

每个内容请求必须有有限超时、固定期望字节数、流结束记录与工具 hash；确切超时值写进执行回执。
超时/断流的对象保持 partial，不将旧文件追加拼接为成功对象。重试需重新核对映射和来源代次，
新尝试使用独立回执。本轮源内容只计划读一次，重复读取需要按缺口另行决定；小型映射与漂移
检查的额外读取须与大内容字节分别统计。

## 每对象的实际验收

1. 同一 capture-set 记录 UTC 起止时间、工具/来源摘要、源实体和固定范围、前后映射与挂载观测。
2. 远端读取的实际字节数等于期望长度，原始流 SHA256 与主机完整解压所得流 SHA256 相同。
3. 主机保存压缩归档自身 SHA256；完整解压校验包含 gzip 尾部/长度检查，不能只验证压缩文件可打开。
4. 前后映射或文件 stat 漂移、缺少结束记录、长度不符、CRC/解压错误、权限/容量/超时均有明确结果；
   不把失败对象记作成功，也不为凑齐集合读取排除内容。
5. 文件对象另记录实际来源、解析后的链接关系、mode/uid/gid、必要元数据和内容 hash；未采的 xattr/
   ACL 必须成为恢复缺口。静态代码审查应区分磁盘配置、systemd 当前加载态、正在执行的进程与动态
   来源，不能靠相同文件名把这些状态合并。

通过上述检验，只能说明**某时段某对象读取到的内容已完整保存并在主机复核**。本地解压不是第二次
源读取；前后映射稳定不是内容原子性。默认一致性级别为 **BEST_EFFORT**。即使某 root 挂载为 ro，
也不能据此推出所有底层写入都已排除。不会停止服务、冻结文件系统、卸载、重启或改槽来提升等级。
SSH 与现有服务可能继续正常记录日志，本轮不能声称整机没有任何后台写入。

如果以后同一完整源范围再次取得相同摘要、前后映射也相同，最多新增“观察到范围稳定”的证据；
仍不是跨分区原子快照。本轮不预先填写该结论。各对象成功时可以独立交付，集合不齐时保持部分覆盖。

- 当前 A/B 系统与各自 boot、DSP、modem、启动选择、共享状态和程序依赖尚未形成经过恢复验证的组合。

- 保存原始 GPT 异常不等于选定恢复策略；任何修复或重建都需要另一个明确方案。没有写盘指令或
  可自动执行的恢复动作作为本交付的一部分。
- 当前 unit/ExecStop/manager/Panda 的静态退出分析可以缩小未知，但不能证明停止后所有访问者消失，
  也不能保证启动没有 reset/flash/升级副作用。服务隔离和退出验证尚未执行。
- 当前共享参数/校准、设备独有状态、完整应用与依赖树、Panda 实际固件/恢复能力、硬件恢复入口及
  实际写回结果都应分别列出。主机镜像通过归档校验不产生整机可恢复、双板绑定或生产运行许可。

这些范围和验收只消费小型已留存元数据，不读取旧大镜像或任何密钥。实际采集及其结果由本轮主
执行流程记录；本文件没有将计划对象提前标为已完成。
