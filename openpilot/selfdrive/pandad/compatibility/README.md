# Offline dual-Panda contracts and codecs (P0/P1/P2/P3)

Standalone Python standard-library contracts and C++17 CAN codecs against
openpilot `35e78a9d`, panda `a5919516`, opendbc `b3bd79a6`. This package is not
imported by the active pandad. P2 adds explicit native backends, without a runtime factory or installer.

`profiles/unbound.json` loads with every identity/role unset and every permission
false. Registry fixtures must explicitly use synthetic identities and supported
DOS/F4 or RED_PANDA/H7 policy pairs; those names do not identify an actual PCB.
Both boards are required, canonical slots never follow enumeration order,
and peripheral absence must be explicit. Successful registration never enables
device access, CAN TX or firmware operations.

`mock_transport.py` consumes an immutable in-memory script. Reads/writes model
partial results and faults; writes only append intent to a bounded trace. Its
resource limits are fixture limits, not validated USB timing requirements.

`health.py` provides explicit current and SP098-offline version profiles, exact
health/CAN-health layouts, strict semantic checks and capability-aware units.
Wire data is separate from the normalized view. Legacy safety IDs are never
translated to current IDs. A known BRS-without-FD transient remains visible and
is marked inconsistent. Protocol identity does not confer control permission.

`can_codec.h/.cc` provides explicit FD, checked wide input fields, six-byte XOR
framing, exact DLC lengths, fixed-slot host source translations and a bounded
stream parser. Invalid feeds atomically discard their output and poison only
that parser until an explicit local memory clear. No hardware reset is implied.

Use `PYTHONPATH=openpilot/selfdrive/pandad` and import `compatibility`, avoiding
the existing `openpilot.selfdrive.pandad` package initializer and its cereal
dependencies. The outer Song PLUS engineering repository supplies
`tools/validate_panda_compat.py`: it reapplies the independent patch series to a
fresh directory, checks source hashes, compiles host probes with ASan/UBSan,
runs tests with locked Python 3.12.13, and compares native CAN results to an
independent Python bit-formula oracle plus actual locked C header fixtures.

Python tests require `TEST_HEALTH_LAYOUT_JSON` generated by the host probe;
missing fixtures fail, never skip. The probe includes the pinned Panda `board/`
and opendbc repository headers and reports host ABI only. Tests never import
Panda, discover devices, compile MCU firmware or start the original pandad.

P4–P7 still own active runtime integration, whole-group freshness/safety
barriers, F4 firmware, system-level fault handling
and deployment packaging. Existing pandad startup/flash behavior is unchanged
because this isolated package is not connected to that entry point.

## P2 transport contract

`transport.h/.cc` wraps a caller-owned backend and clock with a per-session lock,
finite deadline and permanent cooperative cancellation. Results preserve actual
bytes, confirmed prefixes, unknown remaining progress and the adapter's original
status. Short reads return immediately; only known-zero-byte read timeouts can
retry. Writes never replay, including after short completion, timeout or cancel.
Uncertain/error writes poison that session; another board is never selected as
fallback. One backend/clock/parser belongs to one session and must outlive callers.

`usb_backend` selects a normal-firmware Panda by exact bound serial and DOS/RED
software type, rejects ambiguity, and checks active configuration descriptors for
interface0/alt0 bulk endpoints 0x81/0x03. It excludes bootstub/DFU and never detaches
a driver, resets, clears halt or changes USB configuration/alternate setting.
Construction and default `open_bound` are inert. Explicit device permission AND
`bulk_alt0_verified=true` are required before enumeration. This flag is a future
caller's evidence requirement, not proof from descriptors: the pinned firmware
implements SET_INTERFACE but lacks GET_INTERFACE. No P0 profile can currently
activate this C++ library, and actual alternate state remains unverified.

`libusb_api` is real libusb code behind an injectable API. Every backend owns its
context/handle. Native opening/claiming is outside the transfer-time contract.
Tests inject a fake API; the native link smoke test only constructs an unopened
object and exercises rejected default opening.

`spi_backend` preserves successful current wire requests (4096-byte envelope,
9-byte header, 7-byte reply header, little-endian ID and CRC32; 4032-byte chunks,
first read1013). It emits each chunk once and never resends an uncertain request,
including reads that may already have consumed the MCU queue. NACK returns Busy.
The old concrete SPI files and active pandad path remain byte-identical. The new
SPI adapter intentionally replaces old infinite/retry behavior with bounded
errors; it does not claim error-path equivalence. No USB fallback exists.
`linux_spi_io` links the real spidev syscalls and nonblocking flock, but has an
inert constructor. Explicit open configures mode/bits/speed; it is never called
by acceptance. A synchronous kernel ioctl cannot be forcibly cancelled here.

The frozen budget table is `TIMING-BUDGET.md`. `timing_budget.h` is pure candidate
health/heartbeat/queue policy; actual scheduler and whole-group barrier wiring
remain P3/P4. Passing fake-clock tests is not a real-time hardware guarantee.
The engineering validator `tools/validate_panda_transport.py` cleanly composes
P0/P1/P2 patches, reruns P0/P1, and builds/tests P2 on macOS and Linux under
network/device-node isolation. Linux includes real libusb and spidev linkage;
it is a standalone transport target, not a full active pandad daemon build.

## P3 session and routing layer

`session_registry` validates a typed equivalent of P0's synthetic profile,
canonical fixed slots and the complete supplied inventory. It never discovers or
opens devices. Slot epochs and group generation distinguish lifecycle changes;
positive connection tokens strictly increase for each new handle of an identity.
A repeated live token is idempotent, while a retired token cannot reconnect.
Addresses and enumeration order never become identity. Missing/unknown/duplicate
or replaced boards cannot silently promote a surviving board or change a binding.
Only a new explicit profile/registry can bind a replacement. Counter exhaustion
fails closed. Structural group availability is separate from P4 safety readiness;
real device, CAN TX and firmware permissions always remain false.

`can_router` uses this authoritative registry, P1 codecs and per-slot parsers.
It maps host buses0/1/2 and4/5/6 to local0/1/2 exactly once, rejects reserved buses
and TX receipt flags, enforces bound FD capability, and returns offline simulation
intents. It has no Transport reference, syscall or actual write entry point.
Connection/group changes invalidate queued TX, RX and partial bytes before their
next use; stale callbacks cannot populate a new connection. Bounded queues expose
expiry/overflow/lifecycle loss counters. Original receive times remain attached
to frames through fragmentation and publication. Per-board FIFO order does not
claim hardware synchronization between boards.

The integration test connects P3 routing to actual P2 Transport instances whose
backends are fake-only. Its oracle output is checked independently by locked
Python using the existing P0 profile/registry and independent CAN bit formulas.
No second production JSON profile parser or live activation path is added.
`P3-BUDGET.md` records candidate queue and timestamp bounds; the outer engineering
runner `tools/validate_panda_sessions.py` replays all four patches and executes
P0/P1/P2 regressions plus P3 on macOS/Linux. Existing active pandad/SPI sources
remain unchanged. P4 must integrate health/safety, production lifecycle events,
configuration/engagement barriers and message consumers before real use.

## P4 integration (current stage)

The earlier P0–P3 sections describe their historical standalone scope. P4 adds
`ControlSession`, `PandadRuntime`, the bounded `PandadLoop`, unchanged-schema
cereal adapters, an explicit `pandad --compat-offline` entry and opt-in Python
consumer policy. See [P4-INTEGRATION.md](P4-INTEGRATION.md) and
[CONTROL-SESSION.md](CONTROL-SESSION.md) for configuration/readback, liveness,
source-age, role and re-engagement contracts. Every backend used by this entry
is an in-memory fake; no physical profile can be activated. The Linux daemon is
compiled and linked including its retained original SPI path, but only its
explicit offline entry is executed. Real deployment permissions remain false.
